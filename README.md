# Persistent Player Bodies (prototype)

Minecraft Java 1.20.1 · Forge 47.4.10 · Java 17

This repository is an **early prototype/scaffold**, not a release-ready implementation. It contains the Gradle Forge project, a registered persistent corpse entity with NBT-backed inventory, server config, an owner-to-entity SavedData index, logout transfer, a vanilla chest-style loot menu, and a best-effort login recovery routine.

## Import and build

1. Install a 64-bit JDK 17 and verify `java -version` reports 17.
2. Open this folder in IntelliJ IDEA or Eclipse as a Gradle project.
3. Let Gradle download ForgeGradle and the Forge 1.20.1 dependencies.
4. Build with:

   ```bash
   ./gradlew build
   ```

   On Windows:

   ```bat
   gradlew.bat build
   ```

5. The mod jar, if the build succeeds, will be in `build/libs/`.
6. Install the jar on both the client and the Forge 1.20.1 server. Start with a disposable test world and backups.

This archive does not include the Gradle wrapper scripts/JAR. Generate them from a local Gradle installation with `gradle wrapper --gradle-version 8.8`, or use an IDE's Gradle tooling. Gradle is not installed in the generation environment, so compilation has not been run here.

## Important safety limitations

Do not use this prototype on a world with valuable items. It is **not yet safe enough for production**: entity insertion, inventory clearing and SavedData registration are separate persistence operations; a crash at the wrong point can duplicate or lose items. The entity also lacks the custom client renderer/spawn-packet implementation required for a polished visible body. These are known gaps, not completed features.

## Manual test checklist

Use two accounts on a disposable dedicated server and make a world backup first.

1. Disconnect with a full inventory including hotbar, armor and offhand; inspect the body inventory.
2. Loot one item with account B; reconnect account A and verify the looted item is not returned.
3. Verify remaining items return and fit in account A's inventory; test a nearly full inventory.
4. Restart the server with a body present and inspect entity/inventory persistence.
5. Try two looters at once and check for item duplication.
6. Reconnect repeatedly and check that items are not duplicated.
7. Put a body in an unloaded chunk and reconnect its owner.
8. Die normally while connected and verify no logout body is generated by the death path.
9. Test enchanted/damaged/named items and shulker boxes.
10. Force-stop the server during logout and recovery, then inspect all items after restart.

Items 7 and 10 are expected to expose current limitations and must pass before this mod can be called complete.

## Architecture

- `PersistentBodies`: mod entry point and registration
- `config/CorpseConfig`: server configuration
- `registry/ModEntities`: entity registration
- `entity/PlayerCorpseEntity`: entity metadata, inventory NBT and interaction/menu provider
- `storage/CorpseSavedData`: persistent owner index
- `event/PlayerConnectionHandler`: logout transfer and login recovery
